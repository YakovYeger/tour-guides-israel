# AGENTS.md — Tour Guides Israel

Non-obvious findings for working in this repo.

## Stack
- **TanStack Start** (Vite 7 + Nitro SSR) fullstack React app, TanStack Router (file-based), TanStack Query.
- Styling: TailwindCSS v4 (`@tailwindcss/vite` plugin, CSS-first config in `src/styles.css`).
- Backend: **remote Supabase** project (Postgres + Auth + Storage). There is NO local DB option — `supabase/` contains only an edge function (`create-checkout`), no `config.toml`/migrations. Do not try to run Supabase locally.
- Payments: **Stripe** (server functions in `src/lib/stripe.ts`, edge function in `supabase/functions/create-checkout`).

## Running (Base44 compose)
- `docker compose -f docker-compose.base44.yml up -d` — single `web` service, `node:22-slim`, source bind-mounted at `/app`, `node_modules` in an anonymous volume, runs `npx vite dev --host 0.0.0.0 --port 3000`.
- Preview: host port 3000. Vite `server.allowedHosts: true` is set in `vite.config.ts` so the preview's external hostname is accepted.
- First boot runs `npm install` inside the container (~15s) before Vite starts.

## Env / secrets
- `VITE_SUPABASE_URL` is a public project URL, set inline in compose (from `.env.example`).
- The app **boots and renders the marketing pages without any secrets**: the browser Supabase client is `null` when `VITE_SUPABASE_ANON_KEY` is missing, and data queries degrade to empty results (useQuery catches the null-deref error). So the home/region/theme/testimonial sections render; only guide data, auth, bookings, and payments need credentials.
- External secrets (Supabase anon + service-role keys, Stripe keys, optional Google OAuth) are delivered via `/run/base44/app.env` (referenced by `env_file` in compose). They are NOT required to boot.

## Quirks
- `src/routeTree.gen.ts` is committed and regenerated by the router plugin on dev start.
- `import.meta.env` is used for both client (`VITE_*`) and server-side Supabase/Stripe config.
- i18n: en/he with RTL support (`src/lib/i18n/config.ts`, `src/messages/`).

## Verify it works
- `curl -sf -H "Host: external-preview.example.com" http://localhost:3000/` → 200 with `<title>Tour Guides Israel ...`.
- A dev module must load from the external host too: `curl -sf -H "Host: external-preview.example.com" http://localhost:3000/src/routes/__root.tsx` → 200.
